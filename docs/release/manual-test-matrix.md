# Manual Release Test Matrix

This matrix covers browser-only behavior that the automated Vitest suite and
`scripts/verify-build.mjs` cannot prove on their own: real Chrome rendering,
real permission grants, real `chrome.*` API side effects, and real
accessibility tooling. Rows are only marked **Passed** when someone (human or
an agent with real Chrome DevTools access) actually exercised that row
against a loaded `dist/` build and observed the result. Untested rows stay
marked **Not yet executed** — never guessed or assumed.

### Findings from this session (fixed before the above build was tested)

1. **Dead "More options" header button.** Existed unwired since the original
   scaffold commit; clicking/activating it did nothing (no menu, no dialog,
   not even a disabled state) despite its tooltip promising "More options."
   No unassigned functionality existed to attach it to across all 9 feature
   loops. **Fixed:** removed the control entirely
   (`fix: remove the non-functional "More options" header button`).
2. **"1 tabs" pluralization bug.** `TabsToolbar`'s visible-tab-count summary
   always used the plural form, so narrowing to exactly one visible tab
   showed "1 tabs" instead of "1 tab." An existing automated test had
   encoded this wrong string as the expected value, which is why the unit
   suite never caught it. **Fixed:** corrected the pluralization and the
   test's assertion
   (`fix: pluralize the toolbar's visible-tab count correctly`).
